## Findings reviewed

### 1. Swift Evolution SE-0553 — Task Identity

SE-0553 entered active review on 2026-09-23 and runs through 2026-10-07.

The proposal exposes a cheap process-local identity for Swift concurrency tasks through proposed APIs including `Task.currentID`, `Task.id`, `UnsafeCurrentTask.id`, and the opaque `Task.ID` / `TaskID` type. Its intended use is high-frequency tracing, structured logging, profilers, custom executors, lock-free side tables, and other instrumentation where the current closure-shaped `withUnsafeCurrentTask` path or pointer-identity workarounds are unsuitable.

The proposal specifies a task ID that is process-unique, never reused, stable for the task lifetime, and explicitly not meaningful as a cross-process identity.

Canonical change: YES — added to `Swift/Evolution-Watch.md` as active review / PROPOSED guidance.
Action change: NO — no implementation action was created while the proposal remains in review; agents are told not to replace production tracing/task-correlation code until acceptance and toolchain/runtime availability are verified.

### 2. Swift Evolution SE-0548 — resignRemoteID for remote distributed actor references

SE-0548 was accepted on 2026-09-23.

The proposal adds `DistributedActorSystem.resignRemoteID(_:)`, invoked when a remote distributed actor proxy is deinitialized. This closes the lifecycle gap for custom distributed actor systems that need to account for remote references and release connection/resources when references disappear.

The proposal includes a default protocol implementation for compatibility and states that the emitted call is back-deployment-compatible; older runtimes simply do not make the callback.

Canonical change: YES — added to `Swift/Evolution-Watch.md` as ACCEPTED but explicitly **not yet treated as shipping** until toolchain availability is separately verified.
Action change: NO — this is niche and toolchain availability has not been promoted. Project-specific work should only be generated for repositories that implement a custom `DistributedActorSystem`.

Apple's current App Store Connect help now makes multiseat purchase configuration an explicit current concern for auto-renewable subscriptions.

Key details recorded:
- multiseat purchase configuration is turned on by default for auto-renewable subscriptions;
- subscriptions created before 2026-09-14 that do not use StoreKit 2 or that have Family Sharing enabled are opted out by default;
- availability can be configured across the App Store, Apple Business, and Apple School Manager;
- Apple Business and Apple School Manager require multiseat to be enabled for subscription sales;
- Volume Purchasing launches 2026-10-22;
- Group Purchases are planned for winter 2026;
- when multiseat and Family Sharing are both enabled, only the group purchaser's entitlement participates in Family Sharing.

Canonical change: YES — expanded `Distribution/App-Store-Connect-and-Submission.md`.
Action change: YES — added APPLE-020 to audit subscription defaults, StoreKit 2 readiness, Family Sharing interaction, storefront availability, and Bundle/Suite program fit.
